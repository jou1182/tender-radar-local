# رادار المنافسات

تطبيق محلي عربي لرصد منافسات منصة اعتماد، مقارنة الجديد والمتغير، وتجهيز المنافسة للتحليل واتخاذ قرار مبدئي دون حفظ بيانات الدخول أو تنفيذ شراء أو تنزيل تلقائي.

## الوضع الحالي

- واجهة React/vinext عربية على `http://localhost:3000`.
- خدمة محلية للمزامنة على `http://127.0.0.1:4318`.
- SQLite هو مصدر الحقيقة في `.radar-data/radar.sqlite`.
- بيانات العرض التجريبية منفصلة في `app/demo-tenders.ts` ولا تدخل SQLite.
- البيانات التاريخية السابقة محفوظة للمرجعية في `app/legacy-observed-tenders.ts` ولا تُحمّل في واجهة التشغيل.
- Workflow n8n للمرحلة الأولى في `automation/n8n/radar-phase-1.workflow.json`.
- مزامنة P1 تحفظ checkpoint بعد كل صفحة ومنطقة، وتستأنف الجولة الجزئية دون المساس بآخر لقطة مكتملة.
- قراءة P2 تفتح تبويبات تفاصيل المنافسة وتحفظ النصوص الظاهرة والحقول المنظمة وأسماء المرفقات الظاهرة فقط في SQLite Schema v3.
- فحص التفاصيل يعمل لمنافسة واحدة أو لعينة محكومة من منافسة إلى ثلاث منافسات، ولا ينفذ تنزيلًا أو شراءً أو انضمامًا.
- Chrome المخصص يفتح كنافذة بشرية عادية، ثم تتصل به خدمة القراءة محليًا بعد إكمال تسجيل الدخول يدويًا.
- التحليل المحلي عبر Ollama: **مُوصَّل كافتراضي `nemotron-3.5-lightning:latest` عند التفعيل الصريح** (`RADAR_AI_ENABLED=true` + `RADAR_AI_PROVIDER=ollama`)؛ الافتراضي يبقى `stub` بلا env vars، وتحليل المستندات الحقيقية مؤجَّل.
- مخطط n8n لتشغيل التحليل (`workflows/p4a-local-analysis.json`) **مُفعّل ومُختبَر حيًا بالمسار الكامل** (رادار ← n8n ← رادار ← Ollama) في P4-UAT0.
- **النسخة الحالية: `1.0.0`** — جاهزة لوسم `v1.0.0-local` في مهمة منفصلة لاحقة (لا وسم في هذا الـcommit).

## المتطلبات

- Node.js `>=22.13.0` مع دعم `node:sqlite`.
- Google Chrome.
- `pdftotext` (حزمة poppler) و**Python 3 + `pip install pymupdf`** — مساران بديلان
  لاستخراج نص PDF عند فشل المستخرج المضمّن (خطوط بلا ToUnicode أو فقدان محتوى
  عربي صامت)؛ الرادار يتدهور بأمان بتحذير صريح إن غاب أي منهما، لكن أفضل نتائج
  الاستخراج تتطلب كليهما مثبَّتين.
- Docker Desktop وn8n اختياريان لتشغيل مخطط التحليل عبر n8n (`workflows/p4a-local-analysis.json`).
- Ollama اختياري — للتحليل المحلي عند التفعيل الصريح (النموذج الافتراضي `nemotron-3.5-lightning:latest`).

## التشغيل

```powershell
npm install
npm run build
npm run radar
```

أو افتح `تشغيل-الرادار.cmd`.

## الاختبارات

```powershell
npm test
```

تتحقق الاختبارات من البناء، الواجهة العربية، سلامة المزامنة المحلية، Workflow n8n، فصل بيانات العرض، ترميز UTF-8، استمرارية SQLite، pagination حتى 100 ظهور، حفظ/استئناف الجولة الجزئية، واستخراج وحفظ تفاصيل المنافسات دون شراء أو تنزيل.

## حدود الأمان

- المستخدم يسجل الدخول بنفسه داخل نافذة Chrome المخصصة للرادار.
- لا يحاول الرادار حل CAPTCHA؛ يحفظ الجولة ويعرض `captcha-required` لتكمل التحقق بنفسك ثم تستأنف.
- لا تُخزن كلمات مرور أو OTP أو Cookies داخل قاعدة الرادار.
- لا يتم شراء كراسة أو تنزيل ملف أو الانضمام أو تقديم عرض تلقائيًا.
- عند انتهاء جلسة اعتماد تتوقف المزامنة وتطلب تسجيل الدخول مجددًا.

## المسارات المهمة

- `app/page.tsx`: الواجهة.
- `scripts/etimad-sync-service.mjs`: خدمة المزامنة المحلية.
- `scripts/lib/radar-chrome-session.mjs`: فتح Chrome البشري والاتصال المحلي بعد تسجيل الدخول.
- `scripts/lib/sync-plan.mjs`: خطة المناطق والصفحات وحد 100 ظهور.
- `scripts/lib/radar-repository.mjs`: SQLite migrations وطبقة البيانات.
- `scripts/lib/etimad-detail-parser.mjs`: تنظيف حقول التفاصيل العربية وتصنيف أسماء المرفقات الظاهرة.
- `tests/details-p2.test.mjs`: اختبارات P2 للحفظ والتاريخ وحد العينة وحواجز الأمان.
- `tests/repository.test.mjs`: اختبارات SQLite وفصل البيانات والترميز.
- `دليل-تشغيل-الرادار.md`: دليل المستخدم.

للسياق الكامل وخطة المراحل التالية راجع `..\وثيقة-تسليم-رادار-المنافسات.md`.
