# مراجعة Codex الانتقائية — P3-B0

- مصدر المراجعة: فرع `kimi/p3b-approval-gate`
- commit المصدر: `559b81b33f0a921603417113491effd0f13687e8`
- نقطة الأساس: `cbb0556fad1af7facadd1d46b5eeb36850f4c68e`
- لم يُدمج فرع Kimi؛ نُقلت التغييرات إلى `main` دون commit ثم روجعت وعُدلت.

## ما تم الاحتفاظ به

- Schema v5 وسجل الموافقات ووظائف التنزيل.
- manifest ثابت وبصمة SHA-256 وحدود 5 ملفات و100MB للملف و300MB للدفعة.
- حالات الإتاحة المسموحة: `free-available` و`purchased-available` فقط.
- موافقة مدتها عشر دقائق، استخدام واحد، وتأكيد إضافي للكراسة المدفوعة.
- محوّل إنتاج معطل ومحاكي اختبارات بلا شبكة أو Chrome.
- واجهة عربية للموافقة، واختبارات الهجرة والحدود والمسارات.

## إصلاحات Codex قبل الاعتماد

1. فُصل إنشاء الطلب عن التأكيد: `approval_intent` المعلق لا يمنح أي صلاحية، والتأكيد البشري وحده ينشئ `approval`.
2. أُلغي استهلاك الموافقة تلقائيًا في B0؛ المحوّل المعطل لا يهدر موافقة صالحة.
3. أُبطلت موافقات v4 القديمة التي لا تحمل نطاقًا أو بصمة أو انتهاءً بدل تركها قابلة للاستهلاك.
4. أصبح manifest إلزاميًا عند الاستهلاك ولا توجد مطابقة ضمنية.
5. أضيف شرط Origin محلي إلى مسار التأكيد، بينما n8n لا يملك أي عقدة تصل إلى سطح الموافقات.
6. أضيف اختيار صريح لملف واحد إلى خمسة ملفات بدل اختيار جميع الملفات تلقائيًا.
7. اسم التخزين الفعلي أصبح SHA-256 داخليًا مع الاحتفاظ باسم العرض كبيانات وصفية فقط، ومنع أسماء Windows غير الآمنة وADS.
8. أخطاء بوابة الموافقة لم تعد تغيّر حالة المزامنة إلى `login-required`.
9. ثُبتت الصيغ المسموحة حرفيًا: PDF وExcel وWord وPowerPoint وZIP وRAR و7Z؛ لا CSV أو TXT.

## الحالة النهائية لـP3-B0

- لا يوجد تنزيل حي أو شراء أو دفع أو انضمام أو تقديم عرض.
- لا تستخدم بوابة B0 جلسة Chrome ولا Cloudflare ولا cookies.
- الموافقة المسجلة تبقى غير مستهلكة، لكن لا يوجد محوّل إنتاج قادر على استخدامها.
- تفعيل P3-B1 يتطلب مراجعة مستقلة وعينة مجانية من ملف واحد بعد موافقة جديدة.
